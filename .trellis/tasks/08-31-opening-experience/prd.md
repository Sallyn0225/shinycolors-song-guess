# 开场动画、问候语音与环境 BGM

## Goal

给站点加一段开场：打开网页时全屏覆盖品牌 splash（brand.png + 标题 + 描述 + 点击提示），
点击后解锁音频并播放 28 人中随机一位的问候语音，语音结束后渐入循环环境 BGM，
splash 化开退场交回首页。BGM 只在已有背景视频的三屏（首页 / 大厅 / 房间）存在。

## 背景与硬约束

### 语音无法在点击之前播放

原始需求是「动画加载后稍稍往后就播语音，像手游那样」。手游能这么做是因为原生 app
没有自动播放限制；**浏览器必须有一次真实用户手势才允许 AudioContext 出声**，
这正是 `apps/web/src/App.tsx:38` 那条注释警告过的坑（漏掉手势，线上第一题全场静音，
本地热重载永远不复现）。

因此触发点定为 splash 上的那一次点击，节奏保持不变：

```
页面加载 → splash 入场（无声）→ 等待点击
   ↓ 点击（解锁 AudioContext）
   ↓ ~180ms
问候语音起播 + 角色署名淡入      ← splash 仍在场
   ↓ 语音自然结束
BGM 渐入（2.5s）+ splash 化开退场 → 首页入场
```

已与用户确认：不做无手势 autoplay 探测（成功与否随浏览器 MEI 分数而变，
会造成「有时有声有时没声」的体验分裂）。

### 素材实测数据

| 素材 | 现状 | 结论 |
|---|---|---|
| `brand.png` | 1839×855 **RGB 无 alpha**，黑底发光 logo，1.3MB | 它本质是 premultiplied alpha，构建时精确还原成真 alpha，再预合成到深紫底板输出不透明图（见 design.md 第 7 节） |
| `opening-greeting/*.wav` | 28 段，48kHz mono s16，**3.72s–6.56s**（中位 4.64s），共 12MB | 必须转 Opus；随机选中后只下 1 段 |
| 角色头像 | `cf-static.shinycolors.moe` `characters/icon_circle/001–028.png`，**54×54 RGBA，无更大尺寸** | 行内呈现 **不得超过 40 CSS px**，放大即糊 |
| 曲库切片 | 1464 个，**全部恰好 15s**，同曲起点不连续（30 / 60.5 / 92…） | 同曲连播会有乐句跳变，靠交叉淡化盖接缝 |

编号 `001`–`028` 已逐张视觉核对，与 `opening-greeting/` 的 28 个文件名一一对应，
`029` 返回 404，确认曲库外无第 29 人。

## Requirements

### R1 · 品牌 splash

- R1.1 打开网页时全屏覆盖，位于所有界面之上。
- R1.2 承载三段文案，**逐字照用**：标题「闪彩猜歌游戏」、描述「听一段伴奏，选出它是闪彩哪首歌」、
  提示「点击任意处开始进入游戏」。
- R1.3 展示 `brand.png`，带一定透明度地融入界面，而不是贴一张不透明的图。
- R1.4 沿用既有视觉世界（白底 + 虹彩镭射膜 + 斜切 + 宽字距），splash 不是新世界。
  全站唯一一块深色压缩成 logo 底板**一张卡**，不铺满一屏。
- R1.5 整屏可点；同时提示行是真 `<button>`，Enter / Space 可达。
- R1.6 各层错开入场，退场与入场互为镜像（模糊转清晰 / 清晰转模糊）。

### R2 · 问候语音

- R2.1 每次开场从 28 段中随机取一段播放。
- R2.2 **音量固定，不可调，不受音量滑块影响**，取 80%。
- R2.3 语音播放期间 splash 不退场；同时淡入「今天是 <角色名> 来迎接你」+ 角色头像。
- R2.4 语音自然播完才进入 BGM 渐入，不截断。
- R2.5 下载或解码失败时静默跳过，直接进 BGM——开场不因为一段问候而卡住。

### R3 · 环境 BGM

- R3.1 复用曲库既有 15s 切片，不新增音频素材。
- R3.2 循环播放，永不静止。
- R3.3 **同一首歌连播 3–4 个切片再换曲**（每曲约 45–60s），切片之间交叉淡化。
- R3.4 **音量固定且低于默认音量，不受音量滑块控制**。
- R3.5 **静音开关必须同时切断 BGM**——滑块位置不影响 BGM 音量，但静音要能让世界安静。
- R3.6 只在已铺背景视频的三屏（`start` / `lobby` / `room`）播放；
  **进入 `play` / `karuta` 立即淡出**，游戏过程中绝不出声。
- R3.7 首页提供一个极小的 BGM 独立开关，选择记在本机。
      位置定在**棱镜光带正上方、水平居中**（产品方指定），做成可扩展的 `ToolRail`
      —— 后续还会往这一排加图标按钮。
      图标沿用 `ui/Icon` 那套手绘 SVG（24 网格 / 1.8 描边 / **方头方角**），
      **不引 Lucide 或 Font Awesome**：那两套都是圆头圆角，与这个零圆角的世界冲突，
      一屏里出现两种笔法比少一个图标难看得多。需要新形状就照 24 网格重画一枚。
- R3.8 BGM 不得污染 `analyser` 频谱——`PrismRail` 读的就是它，混进 BGM 会让可视化脱离题目音频。

### R4 · 找回对局时让路

- R4.1 检测到本地仍留座位凭证（`socket.hasResumeToken`）时，splash 降级为单屏「点击继续对局」。
- R4.2 该路径**不放问候语音、不起 BGM**——对局在跑，不能拿开场动画拖时间。

### R5 · 资源与无障碍

- R5.1 `brand.png` 转 WebP，目标 < 150KB。
- R5.2 28 段语音转 Opus，**只下载随机选中的那一段**。
- R5.3 28 张头像本地化后转 WebP，同样只下 1 张；**不在运行时从第三方 CDN 拉取**。
- R5.4 `prefers-reduced-motion` 下 splash 仍出现（它承担手势），入场改为瞬时淡入、呼吸动效关闭。
- R5.5 全部文字对比度守住 DESIGN.md 既有底线；深紫底板上的文字按 The Tinted-Surface Rule 对着合成色测。

## 签名阻塞记录（`audio.ts`）

`quality-guidelines.md` 的 Layer boundary 一节要求：禁区模块的签名如果真的挡路，
**停下来记在 prd.md，不许顺手改**。这里记一次。

- **挡路的是什么**：`AudioEngine` 的 `ctx` 与 `master` 都是 `private`，对外只有
  `unlock()` / `setVolume()` / `play()`。问候语音与 BGM 必须挂在**同一个 AudioContext**
  上（浏览器对 AudioContext 实例数有上限，且第二个实例同样需要手势解锁），
  却又必须绕开 `master`（否则受音量滑块控制，违背 R2.2 / R3.4）和 `analyser`
  （否则污染 `PrismRail` 频谱，违背 R3.8）。现有 API 无法表达「同 ctx、不同链路」。

- **拟议改动**：只加一个只读 getter，不改任何既有方法的行为、参数或调用路径。

  ```ts
  /**
   * 旁路输出。开场问候与环境 BGM 挂在这里：它们既不受音量滑块管（走 master 就会），
   * 也不能进 analyser（会污染 PrismRail 的频谱）。
   * 返回 null 表示 AudioContext 还没被手势解锁。
   */
  get bypass(): { ctx: AudioContext; out: AudioNode } | null
  ```

- **为什么是安全的**：纯加性，返回既有的 `ctx` 与 `ctx.destination`；
  题目音频的调度、`getOutputTimestamp()` 补偿、AAC 兜底、LRU、频谱六条既有路径
  一行未动。`git diff -- src/audio.ts` 会有输出，这是**记录在案的有意改动**，
  不是 UI 工作的副作用。

- **被拒绝的替代方案**：① 另建第二个 AudioContext——要再走一次手势解锁，
  且两个 ctx 的 `currentTime` 不同源，交叉淡化的调度会漂；
  ② 走 `master` 再反向补偿滑块增益——滑到 0 时无法补偿（除以 0），且仍进 analyser；
  ③ 用 `<audio>` 元素播 BGM——起播延迟不可预测、`volume` 分步改有 zipper noise，
  正是 `audio.ts` 开头列出的、当初弃用 `<audio>` 的那几条理由。

## 不做（Anti-goals）

- 不尝试无手势 autoplay 探测。
- 不给 splash 加「跳过」按钮——整屏都可点，跳过按钮是同一个动作的第二个入口。
- 不改动 `audio.ts` 既有 API 的行为、`net/ws.ts`、`api.ts`、`features/*` 的逻辑。
- 不把 BGM 带进 `play` / `karuta`，理由同 DESIGN.md 里背景视频那条。
- 不在 splash 上重复首页的曲库统计、难度说明等首页已有内容。

## 实现期新增的取舍（记录在案）

- **首页的垂直预算被这次改动用尽了。** 加工具条那一行 44px 之前，1366×678 上
  实测 doc 674.6 / vp 678，只剩 3.4px。这一行是靠 `py` 降一档 + section 与音量组的
  `mt` 各降一档换来的，加完之后四档实测：1366×678 溢出 16px，1440×810 / 1536×774 /
  1920×990 都装得下。**没有为最后那 16px 继续压** —— 再压就得把 padding 收到贴边或者
  动标题组的间距，代价是整页处处紧绷；而「必须一屏装下」是牌场那条规矩
  （The Both-Territories Rule），首页没有，`.sc-vfit` 的 safe center 本就管着这种情况。
- **开场遮罩是 Ambient-Veil Rule 唯一被批准的例外。** DESIGN.md 写着背景视频
  「读不出是哪一支 MV 才算调对」，产品方明确拍板入场动画里勉强看得出没关系，
  所以那里的幕只压到 0.20。代码注释已标明这不是漏调的档。

## Acceptance Criteria

### 开场时序

- [ ] 首次打开网页出现全屏 splash，三段文案与 R1.2 逐字一致。
- [ ] 点击任意处后约 180ms 起播问候语音，且每次刷新听到的角色随机变化。
- [ ] 语音播放期间 splash 仍在场，角色名与头像已淡入，且名字与听到的声音是同一人。
- [ ] 语音播完后 BGM 才开始渐入，splash 随之退场，首页入场动画接上。
- [ ] 键盘 Tab 到提示按钮后按 Enter，走完与鼠标点击完全相同的流程。

### 音量语义

- [ ] 把音量滑块拖到任意位置，BGM 与问候语音的响度都不跟着变。
- [ ] 打开静音，BGM 立即停止；关闭静音后恢复。
- [ ] 关掉 BGM 开关后 BGM 停止，刷新页面后仍是关闭状态；题目音频不受影响。

### BGM 行为

- [ ] 在首页静置 3 分钟，BGM 一直有声、从不静止，换曲处听不到爆音或突然的响度跳变。
- [ ] 连续听到的若干片段中，同一首歌会连着放 3–4 段再换曲。
- [ ] 从首页点难度进入答题屏，BGM 在题目起播前已经完全淡出。
- [ ] 答题屏与牌场全程无 BGM。
- [ ] 从答题屏退回首页，BGM 重新渐入。
- [ ] 单人答题的 `PrismRail` 频谱只随题目音频起伏，与 BGM 无关。

### 找回对局

- [ ] 1v1 对局中刷新页面，出现的是「点击继续对局」的降级 splash，不播语音、不起 BGM。

### 资源与降级

- [ ] 首屏新增的图片资源合计 < 150KB（WebP 后的 brand + 1 张头像）。
- [ ] 网络面板确认：只请求了 1 段语音、1 张头像，不是 28 段 / 28 张。
- [ ] 断网时 splash 正常出现，点击后无语音但仍能进入首页。
- [ ] 运行时不存在任何指向 `cf-static.shinycolors.moe` 的请求。
- [ ] 开启 `prefers-reduced-motion` 后 splash 仍可点击进入，无入场与呼吸动效。

### 不回归

- [ ] `pnpm -r typecheck` 与既有测试全绿。
- [ ] 单人猜歌与 1v1 牌场的音频时序、判定、频谱与改动前一致。
- [ ] 服务端仍不经 HTTP 暴露 `sliceId`（`catalog.ts` 的红线）。
