# 上线 29 首新曲（HOPEFUL FE@THERS 28 首 solo + 泡沫に染まる）

## Goal

把 `闪猜歌即将上线曲目/` 里的 29 首伴奏纳入曲库并上线：玩家在单机猜歌与 1v1 空札領地戦里
都能听到并猜出它们，首页 / 大厅 / 健康检查报出的规模数字同步为新值。

---

| 项 | 事实 |
|---|---|
| 数量 | 29 个 WAV：28 首 solo + 1 首 8 人合同曲 |
| 来源 | 28 首 = 2026-09-16 发售的三张 HOPEFUL FE@THERS（-Stella- / -Luna- / -Sol-，LACA-25301/302/303）；1 首 = シャニソン 2026-08-01 新夏曲「泡沫に染まる」 |
| 形态 | 44100Hz / 2ch PCM WAV，**无任何标签**，元数据只能从文件名与目录结构重建 |

| 现役曲库 | 243 首 / 1458 切片 → 本次后应为 **272 首 / 1632 切片** |

## Requirements

### R1 · 29 首全部进曲库并可被抽到

- 增量落地：曲库 243 → **272** 首，切片 1458 → **1632** 个（29 × 6）。
- 单机（简单 / 困难）与 1v1（发牌、空札）四条抽题路径都要能抽到新曲，
  且新曲进入干扰项池时不得破坏既有的「易混淆组最多取 1 首 / 永不互为干扰项」约束。
- 新曲的 6 个切片必须满足 `planSlices` 的常规约束（非降级），`degradeLevel >= 3`
  的要人工复核——本批时长 163~269s，预期全部 L0。

### R2 · 演唱者归属正确

- 28 首 solo：归到该偶像所属组合（`unit` = 8 个常设组合之一），显示名是 `角色名 (CV.声優名)`。
- 「泡沫に染まる」：8 人跨组合合同曲，`unit = null`、`displayArtist = 風野灯織・月岡恋鐘 他6名`。
- 决议必须走自动规则（`artist-cv`），**不得**为这批曲子往 `data/overrides.json` 加条目——
  override 是给自动规则判不了的曲子用的，滥用会让决议链审计失真。

### R3 · 元数据与现役曲库同形

- ID3：`title` = `<曲名> (Off Vocal)`、`artist` = 演唱者署名（多人用 `/` 连接）、
  `album` = 官方专辑名；编码规格与现役 243 首一致（320kbps CBR / 44100Hz / stereo，内嵌封面流）。
- 目录形态与现役 25 个 Page 一致：`songs/<Page>/<曲名> (Off Vocal) - <署名>/` 下
  恰好 1 个 mp3 + 1 个 jpg，文件名与目录名同 stem。
- **无人声**（本项目的准入红线：带人声的音源会把答案唱出来）。素材准入是人工判断，
  本任务把可自动化的部分做掉，并留下人工复核入口。

### R4 · 现有 243 首的 sliceId 一个都不许变

切片 id 是随机串，唯一映射记录在 `manifest.private.json`。扩容不得让老曲目换 id：
玩家本地战绩（localStorage 按 songId 记）与分享出去的链接都不该因这次上线而失效，
攻击者攒下的对照表也不会因为扩容而失效——那不是扩容，是轮换（`--rotate-ids` 才是）。

### R5 · 规模数字的对外陈述同步

曲库规模散落在首页 / 大厅数据组、健康检查断言、文档与 spec 注释里，且历史上已经漂移过
（233 / 234 / 244 同时存在于不同文件）。本次把所有**「现役规模」陈述**收敛到 272 / 1632；
历史叙述（`.trellis/workspace/` 日志、归档任务）保持原样。

### R6 · 素材准入流程可复用

「闪猜歌即将上线曲目/」是会反复使用的暂存区。这次留下可复用的机械路径：
曲名 / 演唱者 / 专辑的人工判定落在数据文件里，转码、命名、标签写入与批次完整性校验交给工具，
下一个批次不需要重新推理一遍。
