# 本地战绩统计与奖杯面板

> 父任务：`.trellis/tasks/09-03-stats-and-session-fixes`（需求 U2，决策 D1 / D4 / D5）
> 复杂任务：本 PRD + `design.md` + `implement.md`。改动全在 `apps/web`，服务端与协议零改动。

## Goal

让打了很多局的人**留下点东西**：单机每局结算落进本地存储，首页多一枚奖杯按钮，
点开是一屏「我的战绩」——分简单/困难两档看最高分、最低分、场次与走势，
看自己在哪些**组合**上正确率最高、哪些最低，以及具体最容易错的那几首歌。

数据全部只在**当前设备**。没有账号、没有服务端、没有同步。

---

## 背景

- 结算页 `Summary`（`apps/web/src/api.ts:52-62`）里已经有全部原料：难度、总题数、答对数、
  得分、满分、逐题的 `song.id / title / unit / unitColor / correct`。
  **一次网络请求都不用加**，统计是对已经拿到手的数据做一次归并。
- 站内已有「静态表硬编码在 `features/` 里、注释写明重新求值的命令」的先例
  （`features/idols.ts`、`features/library.ts`）。组合的中文/日文名与代表色照此办理。
- 首页光带上方的 `ToolRail` 那一排注释写着「这里还会长，加按钮直接往 children 里塞」——
  奖杯按钮就是它的第五个。

## Requirements

### R1 · 记录：每局单机结算落一次

- 记录点在**结算页拿到 `Summary` 之后**。中途退出（`onQuit`）不产生结算，不记录。
- **按 `sessionId` 幂等**：同一局无论重渲染、StrictMode 双跑挂载、还是返回后再进结算，
  都只计一次。
- 只统计单机（D5）。联机对局不记录，本轮不做。
- 记录失败（无痕模式、存储被策略禁用、配额满）**一律静默吞掉**，绝不能让结算页白屏——
  与 `prefs.ts` 同一条规矩，全部读写包 `try/catch`。

### R2 · 存什么

分**简单 / 困难**两档各存一份（U2 原文「分简单和困难模式」；两档的干扰项强度不同，
混在一起算正确率会让数字随「我打了多少困难」漂移）：

| 维度 | 内容 |
|---|---|
| 分数 | 最高分、最低分、平均分、场次 |
| 正确率 | 累计答对 / 累计题数；单局最高正确率 |
| 走势 | 最近 N 局的得分率（N = 20） |
| 组合 | 每个组合的 出现次数 / 答对次数（用于正确率排行） |
| 单曲 | 每首歌的 出现次数 / 答对次数（用于易错榜） |

- **组合口径（D4）**：只计入 **8 个常设组合 + 全体曲（シャイニーカラーズ）** 共 9 个分组。
  shuffle unit（Team.Luna / 彼岸流 / Σ Desire 等 10 个）与无归属曲目（`unit === null`，19 首）
  **不进组合榜**；它们仍然计入单曲榜与分数/正确率总量。
- 未作答的题（`correct === null`，超时且没选）不计入组合榜与单曲榜的分母；
  模式总量的正确率沿用结算页的口径（`correct / total`），两处口径不同要在代码里写明白。
- 存储要有**版本号**。将来加维度时，读不懂的旧数据一律**丢弃回落到空**，
  绝不做半吊子迁移——统计数据丢了只是可惜，读到半个结构会让整屏崩掉。

### R3 · 展示：一块独立的奖杯屏（D1）

- 首页 `ToolRail` 新增一枚**奖杯**图标按钮，位置在信息（ⓘ）之前或之后由实现定，
  但必须在 GitHub 之前——外链永远收尾。
- 图标要**照 24 网格、1.8 描边、方头方角自己画一枚**进 `ui/Icon.tsx`，
  不许从 Lucide / Font Awesome 直接引（`ui/IconButton.tsx` 顶部那段注释是硬约束）。
- 点开进入独立屏（不是弹窗）。屏内有明确的返回首页入口。
- 屏内顶部是**简单 / 困难**分段切换，切换同时作用于该屏所有数字与图表。

### R4 · 可视化

四块，从上到下：

1. **数字块**：最高分 / 最低分 / 场次 / 平均正确率。复用 `ui/Stat`。
2. **走势**：最近 20 局。**复用结算页那条「折痕带」的语汇**（每局一根竖条，高度是得分率），
   不要引入新的坐标轴语言，也不要引入任何图表库。
3. **组合正确率**：横向条形图，一行一个组合，条长 = 正确率。
   条的颜色可以用组合代表色，但必须遵守 `DESIGN.md` 的 **The Unit-Colour-Is-Data Rule**：
   组合色只能作**图形**，绝不作文字（`#fff68d` 在白底上会直接消失）。
   同时要能一眼看出**最高**与**最低**是哪两个（U2 原文问的就是这两个）。
4. **易错曲目榜**：正确率最低的若干首（含出现次数，出现次数太少的不上榜——见 R5）。
   复用结算页列表行的语汇（缩略图 `/thumb/<id>.webp` + 曲名 + 数字）。

**不引入任何图表依赖**。全部用 SVG / CSS + 站内既有 token 与 `.cut-*` 形状原语。

### R5 · 数字要诚实

- 样本太少的条目不进排行：组合与单曲都要有**最小出现次数**阈值
  （建议组合 ≥ 5 次、单曲 ≥ 3 次，具体值在 design 里定并写进注释）。
  没到阈值的显示为「样本不足」而不是一个 0% 或 100%。
- 曲库有 243 首而一局只有 10 题，单曲榜在很长时间里都会是「样本不足」为主——
  这是**正常且必须如实说出来**的状态，不能靠凑数字把它藏起来。

### R6 · 空态与清除

- 一局都没打过 / 某一档没打过时，要有**明确的空态**：说明这里会有什么、给一条回首页开局的路。
  不能是一屏 0 和空图表。
- 提供「清除本地战绩」入口，**二次确认**后清空。理由：数据存在这台设备上，
  用户得有办法把它拿掉；同时它也是开发与验收期唯一的重置手段。

### R7 · 不动的东西

- 服务端、协议、`api.ts`、`net/ws.ts`、`audio.ts` 一律不动（`api.ts` 是禁区，
  且本任务不需要任何新接口）。
- `features/` 下的**既有**文件不改，只新增（父任务 AC-P4）。
- 结算页除了「多调一次记录函数」之外，视觉与行为不变。
- BGM 与背景视频的判断由 `09-03-result-bgm-continuity` 负责拆分；本任务只往
  **BGM 那一侧**加上奖杯屏的名字，不碰视频那一侧（父任务 AC-P2）。

## Acceptance Criteria

- [ ] **AC1 · 记录幂等**：打一局 → 结算页停留、来回切标签页、刷新页面重进结算 →
      场次只 +1。
- [ ] **AC2 · 分档**：简单打 2 局、困难打 1 局 → 奖杯屏两档的场次分别是 2 和 1，
      最高/最低分互不串档。
- [ ] **AC3 · 最高/最低分**：连打三局，人工记下分数 → 奖杯屏显示的最高与最低与实际一致；
      只打过一局时最高 = 最低 = 那一局。
- [ ] **AC4 · 组合口径**：一局里出现过 shuffle unit 或无归属曲目 → 组合榜里**不出现**它们，
      但那一局的场次、分数、正确率与单曲榜都照常计入。
- [ ] **AC5 · 组合排行可读**：组合榜能一眼看出正确率最高与最低的组合；
      未达阈值的组合显示「样本不足」而不是极端百分比。
- [ ] **AC6 · 空态**：清空数据后打开奖杯屏 → 两档都是设计过的空态，没有 0% 图表和空条。
- [ ] **AC7 · 清除**：清除入口需二次确认；确认后奖杯屏立即回到空态，刷新后仍为空。
- [ ] **AC8 · 存储健壮**：手工把 `localStorage['scg.stats']` 改成 `"{"`、改成 `null`、
      改成一个版本号不认识的对象 → 奖杯屏与结算页都不崩，回落到空态。
- [ ] **AC9 · 无痕模式**：Safari 无痕 / 禁用存储的浏览器里，打一局到结算页不报错、不白屏，
      奖杯屏显示空态。
- [ ] **AC10 · 首页没被撑坏**：奖杯按钮加入 `ToolRail` 后，
      1366×678 / 1440×810 / 1536×774 / 1920×990 / 390×844 / 375×667 六档实测，
      窄屏那一排**不换行**、不出现新的溢出（首页那段布局账见 `screens/Start.tsx` 的注释）。
- [ ] **AC11 · 无障碍**：每张图表有文字等价（`role="img"` + `aria-label`，或 sr-only 摘要）；
      分段切换可键盘操作且有正确的 ARIA 语义；奖杯按钮有 `aria-label`。
- [ ] **AC12 · 纯逻辑有测试**：归并与排行是纯函数并有单测（`features/` 下的既有惯例，
      21 条测试就住在那里）。至少覆盖：幂等、分档、阈值、未作答题、组合过滤、版本回落。
- [ ] **AC13**：`pnpm --filter @scg/web typecheck && lint && test` 全绿。

## Non-Goals

- 不做账号、不做服务端持久化、不做跨设备同步、不做导入导出。
- 不统计联机对局（D5）。
- 不做成就/徽章系统、不做排行榜。
- 不改计分规则与段位划分（`features/grade.ts` 不动）。
- 不给奖杯屏加背景视频（父任务 D2）。
- 不做「战绩图片导出」——`ui/ShareTicket` 是单局战报，本屏不复用它。
