# 全员离线房间即时回收

> 父任务：`.trellis/tasks/09-03-stats-and-session-fixes`（需求 U4，决策 D3）
> 复杂任务：本 PRD + `design.md` + `implement.md`。改动全在 `apps/server`，前端零改动。

## Goal

**房间里一条活连接都不剩的那一刻，房间就没了。**
座位凭证同时作废，重进不再接回一间没有对手的空房——回到首页，自己进大厅重新建房。

---

## 背景：今天要等多久

用户问的那个场景（一人掉线、另一人也退出）今天的实际时序是：

| 时刻 | 发生了什么 | 房间状态 |
|---|---|---|
| T+0 | A 掉线 → `Hub.disconnect` → `room.detach('A')` | 座位 A 留着（等重连），conn = null |
| T+0 | B 主动退出 → `leaveRoom` → `room.leave('B')` | 座位 B 清空 |
| — | 此刻房间 `isEmpty === false`（A 的座位还在）、`allOffline === true` | **仍在 `hub.rooms` 里** |
| T+65s | `abandonedTtlMs` 到期（默认 `disconnectGraceSeconds + 5` = 65s） | 仍在 |
| ≤T+70s | 下一次 `sweep()`（每 5s 一跳）扫到它 | 才被 `dropRoom` |

也就是最长 **70 秒**的窗口里：

- 这间房**还挂在大厅列表**上（公开房时），别人点进去是一间没有对手的房；
- 它**还占着 `MAX_PUBLIC_ROOMS` 的名额**，别人建房会被拒（与 U3 的「已满」提示撞在一起，
  见父任务 AC-P3——那时提示是对的，但占用是假的）；
- A 刷新页面**还能接回去**，接回的是一间只有自己的房。

这个 65 秒的口径是有出处的：`abandonedTtlMs` 的注释写着「**绝不能小于 `disconnectGraceSeconds`**，
小了就等于取消了重连宽限」。那句话对**还有人在等你回来**的房间成立；
对**没有人在等**的房间不成立——留着它谁也没有得到保护。本任务修正的正是这个区分。

## Requirements

### R1 · 判据是「有没有活连接」，不是「有没有座位」

- 一个房间只要满足**没有任何一个座位持有活连接**，就立刻回收。这一条同时覆盖：
  - 两个人都掉线（都是 `detach`，座位还在）；
  - 一个掉线 + 一个主动退出（`detach` + `leave`）；
  - 两个人都主动退出（都是 `leave`，房间变空）；
  - **只有一个人的房间，那个人掉线或退出**（D3 明确接受的连带后果）。
- 「回收」= 走 `dropRoom` 这条唯一出口：销毁定时器、清 `bySeatToken` 索引、出 `rooms` 表、推新列表。

### R2 · 立刻，不等清扫

- 回收发生在**触发它的那次事件的同一条调用栈里**（socket 关闭、或处理 `leaveRoom` 的那一刻），
  不依赖 5 秒一跳的 `sweep()`，也不等任何 TTL。
- `sweep()` 里既有的 `abandoned` 分支**保留为兜底**（防的是某条没有触发 `disconnect` 的异常路径），
  但它的注释要改写成「这是兜底，正常路径已经在事件里回收了」——注释是这份契约的正文，
  留着旧话会让下一个人以为 65 秒才是设计口径。
- `abandonedTtlMs` 这个环境变量与它的默认值**不改**（父任务 Non-Goal：不改配额默认值）。

### R3 · 座位凭证同时作废，重进是一次新连接

- 房间回收后，两个座位的 `resumeToken` 必须从 `bySeatToken` 里消失。
- 之后带旧凭证 `hello` 的客户端收到 `welcome { resumed: false, resumeToken: '' }`——
  这条路径**今天就已经存在且有测试**（`room.test.ts`「凭证无效时明确告知这是一次新连接」），
  前端收到它会退出「正在找回对局」并回到首页（`App.tsx:78-90`）。**因此前端零改动。**

### R4 · 还有人在场时，一切照旧（回归护栏）

这是本任务最容易改坏的一条，必须显式验：

- 一方掉线、**另一方仍在线**时：房间**不回收**，`disconnectGraceSeconds`（60s）的重连宽限
  与 `forfeitIfAbandoned` 的判负逻辑一字不动。
- 掉线方在宽限内重连，仍然接回原座位、拿回牌面、对手仍收到 `peer online`。
- 对局中的所有既有时序（`ARM_TIMEOUT_MS` / 回合窗口 / `OKURI_TIMEOUT_MS` / `REVEAL_MS`）不受影响。

### R5 · 不动的东西

- 不改协议（`packages/shared`），不新增消息与错误码。
- 不改 `Room` 的对局逻辑；`Room` 只可能新增/沿用只读判据（`allOffline` 已经有了）。
- 前端不改。`net/ws.ts` 是禁区，本来也不需要动。

## Acceptance Criteria

- [ ] **AC1 · 用户场景**：A 建房、B 加入、开局；A 断线；B 发 `leaveRoom` 并断开 →
      房间**立刻**（同一次事件循环内，不等 TTL）从 `hub.rooms` 消失；
      大厅订阅者在一个 `LIST_FLUSH_MS`（250ms）内收到不含该房的新列表。
- [ ] **AC2 · 凭证作废**：AC1 之后，A 用原 `resumeToken` 重连 → `welcome.resumed === false`、
      `resumeToken === ''`，且**收不到** `room` / `stateSync`。
- [ ] **AC3 · 双方同时掉线**：两人都直接关连接（都不发 `leaveRoom`）→ 同样立刻回收。
- [ ] **AC4 · 单人房（D3 的连带后果）**：A 建房后独自断开 → 房间立刻消失，凭证作废。
      这一条要写成一个**显式的测试**，因为它是一个被有意接受的行为变更，
      不能靠「碰巧没测到」留在代码里。
- [ ] **AC5 · 回归护栏**：A 掉线、B 在线 → 房间仍在列表里（状态由 `full` 变化与否照旧）、
      A 在宽限内能重连接回原座位并拿回牌面、B 收到 `peer online`。
      既有的两条重连测试必须**原样通过，不许改断言**。
- [ ] **AC6 · 占用口径一致**：公开房上限设为 1，建一间房后全员离线 →
      立刻可以再建一间公开房（父任务 AC-P3 的服务端一半）。
- [ ] **AC7**：`pnpm --filter @scg/server test` 全绿（含新增用例），
      `pnpm -r typecheck && pnpm -r lint` 全绿。

---

## Non-Goals

- 不改 `disconnectGraceSeconds`（60s 的对局内重连宽限，在还有对手时依然完整）。
- 不改 `waitingTtlMs`（15 分钟无人加入的等待房回收）与 `ROOM_TTL_MS`。
- 不做「房间保活/恢复」这类反方向的功能。
- 不给被回收的房间发任何通知（房里没有人能收到）。
- 不改前端的「正在找回对局」等待时长（`RESUME_TIMEOUT_MS`，6s）。
