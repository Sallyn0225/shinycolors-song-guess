# PVP 对局退出与对手退出提示

## Goal

为联机对局补上一条完整的**主动退出**流程：对局中随时可退、退出前二次确认、退出方回到联机大厅、
留守方看到横幅提示并在 10 秒后自动回到房间（可手动跳过）。主动退出与掉线在协议层和 UI 上
必须是两条互不混淆的路径。

## Background

当前实现里主动退出这条路几乎是空的：

- `apps/server/src/ws/room.ts:246` 的 `leave()` 只做 `seats[p] = null` + `clearTimers()`，
  **一个字节都不发给对手**。对局中一方退出，对手停在牌面上，牌还能点但服务端已无回合推进，
  直到 sweep 按 `ROOM_TTL_MS` / `abandonedTtlMs` 把房间回收才结束。
- 等待阶段（Room 屏）一方退出同样不通知，留守方的座位条一直显示对手在座、"准备"按钮仍然可点。
- 对局中根本没有退出入口：只有断线遮罩里的「放弃这局」和结算页的「退出房间」。
- `App.tsx:172` 的 `onExit` 是 `leaveRoom + socket.close()` 回**首页**，不是大厅。
- `ServerMsg.matchEnd.reason` 里的 `'forfeit'` 从创建至今没有任何一处触发过。

掉线路径反而是完整的：`detach()` 广播 `peer{online:false, graceEndsAtServer}`，Karuta 显示
常驻红色横幅并倒计时，宽限到期 `forfeitIfAbandoned()` 判负发 `matchEnd('disconnect')`。
本任务要补的是与它平行、语义相反的另一条路：**人不会回来了**。

## Requirements

### R1 对局中的退出入口与二次确认

- Karuta 屏在对局进行中（`stage !== 'over'` 且自己在线）常驻一个退出入口。
- 点击**不立即退出**，先弹确认层，明确写清后果：退出即判负、无法再回到这一局。
- 确认层提供「确认退出」与「继续对局」两个出口，Esc / 点击遮罩等同于「继续对局」
  （失败方向只能是"留在对局里"）。
- 断线遮罩里的「放弃这局」和结算页的「退出房间」**不加**确认层：前者已经是在一个
  "这局大概率没了"的语境里，后者对局已结束，退出没有任何损失。二次确认只保护
  "误触让一局正在进行的对局作废"这一种情况。
- 房间等待阶段（Room 屏）的「离开房间」也**不加**确认层，理由同上：没有可损失的对局。

### R2 退出方的落点

- 确认退出后：发 `leaveRoom`，**不关闭 socket**，落到**联机大厅**（`lobby` 屏）。
  与 Room 屏的 onLeave 同一条理由 —— 关掉 socket 就要重连、列表要重订阅，
  而用户此刻想做的只是"换一局"。
- 断线遮罩里的「放弃这局」同样落到大厅：socket 断着的时候 `leaveRoom` 发不出去，
  但大厅屏本身会重连并重订阅列表，落点保持一致比落回首页更符合预期。

### R3 留守方的横幅与自动返回

- 服务端在"对局中有人主动退出"时给留守方推一条**新的**服务端消息，携带
  退出者的座位与昵称，以及重置后的 `RoomView`。
- 留守方看到顶部横幅：`<昵称> 已退出房间` + 剩余秒数 + 「立即返回」。
- 横幅出现后牌面立即冻结（不可点、视觉变灰），正在播的音频停止 —— 这一局已经没了，
  让人接着点只会更困惑（与断线遮罩同一条原则）。
- 10 秒倒计时结束，或用户点「立即返回」，落到 **Room 屏**（不是大厅）：
  房间还在、房间码不变、留守方留在座位上，可以直接等下一个人加入。
- **不弹结算、不出战报**：对手跑了的一局没有值得展示的数据。
- 对局已结束（双方在结算页）时一方退出，走同一条横幅路径 —— 留守方也需要知道
  "再战"已经等不到人了。

### R4 主动退出与掉线必须可区分

| | 掉线 | 主动退出 |
|---|---|---|
| 触发 | 连接断开 → `Room.detach()` | `{t:'leaveRoom'}` → `Room.leave()` |
| 对手收到 | `peer{online:false, graceEndsAtServer}` | 新消息（R3） |
| 对手看到 | 红色横幅「掉线了，等待重连 Ns 到点判其负」 | 横幅「已退出房间，Ns 后返回房间」 |
| 座位 | 保留，可用 resumeToken 接回 | 立即释放，凭证作废 |
| 结局 | 宽限到期 `matchEnd('disconnect')` | 房间重置回等待，无 `matchEnd` |

- 掉线路径的任何现有行为都不得改变（宽限时长、`peer` 广播、`forfeitIfAbandoned`、
  重连接回牌面）。
- 主动退出后退出者的 `resumeToken` 必须立即从 `bySeatToken` 移除（现有 hub 逻辑已如此，
  不要在重构里弄丢）。

### R5 等待阶段退出也要通知

- 顺手修掉既有缺陷：房间等待阶段一方退出时，给留守方广播一次 `{t:'room'}`，
  让座位条变回"等待对手加入…"、"准备"按钮变回禁用。这条不走横幅（留守方本来
  就在 Room 屏，没有需要返回的地方）。

## Constraints

- `apps/web/src/net/ws.ts`、`src/audio.ts`、`src/api.ts`、`src/features/*` 是禁区
  （见 `.trellis/spec/web/frontend/index.md`），本任务不应需要改动它们。
- 服务端无数据库，房间状态全在内存，退出流程不得引入任何持久化。
- 新增的服务端消息必须是**独立消息**，不得复用 `error` 或 `roomClosed`：
  前者语义是"这次操作没成功，你还在房间里"，后者是"房间没了"，都读不出"对手走了但房间还在"。
- 房间在对局中被退空一半后必须能重新开局：`state`、`reading`、`roundPhase`、
  `clipTokens`、`rematchVotes`、定时器、留守方的 `ready/taken/otetsuki` 全部要复位，
  否则 `Room.status` 会一直停在 `'playing'`，房间既不出现在大厅列表里也无法再准备。

## Acceptance Criteria

- [ ] 对局进行中，Karuta 屏有可见的退出入口；点击弹出确认层，取消后仍在原对局、
      牌面状态与回合计时不受影响。
- [ ] 确认退出后，退出方落到联机大厅并能立即看到房间列表（socket 未断开）。
- [ ] 留守方在对手退出后立刻看到横幅（昵称正确）、牌面冻结、音频停止。
- [ ] 横幅倒计时 10 秒后自动落到 Room 屏；点「立即返回」可提前落地，二者落点一致。
- [ ] 落回 Room 屏后：房间码不变、自己仍在座、对手位显示"等待对手加入…"、
      "准备"按钮为禁用态；有第三人用房间码加入后可正常再开一局。
- [ ] 该房间在退出后重新出现在大厅列表中且状态为 `waiting`（公开房）。
- [ ] 掉线路径行为无变化：拔网线一方的对手仍看到「掉线了，等待重连」红色横幅与宽限倒计时，
      宽限内重连能接回牌面，宽限到期收到 `matchEnd(reason:'disconnect')`。
- [ ] 等待阶段一方离开，留守方的 Room 屏对手位立即变回"等待对手加入…"。
- [ ] 双方都离开（一退一断、或两个都退）时房间照常被立即回收，
      `dropIfDeserted` 的既有行为不退化。
- [ ] `pnpm -r test` 与 `pnpm -r typecheck` 全绿；服务端新增覆盖
      "对局中退出"、"等待阶段退出"、"退出 ≠ 掉线" 三条路径的测试。

## Out of Scope

- 不做退出的战绩/统计记录（PVP 目前没有任何本地战绩，`records.ts` 只服务单人模式）。
- 不做"退出后可用房间码重新加入原房间"的邀请回流。
- 不改再战（rematch）投票机制本身。
- 不给 Room 屏的「离开房间」和结算页的「退出房间」加确认层（见 R1）。
