# 建房弹窗内显示上限已满

> 父任务：`.trellis/tasks/09-03-stats-and-session-fixes`（需求 U3）
> 轻量任务，**PRD-only**：改动全在 `apps/web/src/screens/Lobby.tsx`，无协议改动、无服务端改动。

## Goal

在建房弹窗里点「创建」而被服务端拒绝时，**拒绝的话要出现在弹窗里**。
今天它出现在弹窗**背后**的大厅页上，等于没说。

---

## 背景：这条提示是怎么丢的

服务端拒绝建房的路径是齐全的（`apps/server/src/ws/hub.ts:361-406`），公开房满时回的是：

```ts
{ t: 'error', code: 'server_busy', message: '公开房间已满，可以创建私人房间' }   // 私人房开着
{ t: 'error', code: 'server_busy', message: '公开房间已满，稍后再试' }           // 私人房关着
```

前端也接住了（`Lobby.tsx:177-179` → `setError(msg.message)`），但：

1. 那个 `error` 只画在大厅页的 `Lobby.tsx:343` 处，而此刻**弹窗还盖在上面**——
   `create()` 从不 `setCreating(false)`（`Lobby.tsx:207-220`），提交失败弹窗理应留着，但它把提示挡住了。
2. 弹窗里点完「创建」到错误回来之间**没有任何状态变化**，读起来就是「点了没反应」。

所以这不是「提示放错了位置」，是**建房这条提交路径在弹窗内完全没有反馈面**。

---

## Requirements

### R1 · 弹窗开着时，建房错误显示在弹窗里

- 建房弹窗开着期间收到的 `error`，渲染在弹窗内部（「创建」按钮附近，提交结果该出现的地方），
  **不再**只画在弹窗背后的大厅页上。
- 弹窗**保持打开**。这一条是刻意的：公开房满时服务端给的是
  「公开房间已满，可以创建私人房间」——那是一条**可执行的建议**，玩家得留在弹窗里
  才改得了可见性重试。关掉弹窗等于把建议扔掉。
- 弹窗内的错误在下一次点「创建」时清空，关闭弹窗时也清空（下次打开是干净的）。
- 大厅页那条错误提示**保留**：房间码加入（`joinByCode` / `joinRoom`）的失败仍然走它，
  那条路径没有弹窗。

### R2 · 提交中要有状态

- 点「创建」后进入提交中：按钮禁用（沿用 `Button` 既有的 `disabled` 语汇），
  直到收到 `room`（成功，弹窗随大厅屏一起卸载）或 `error`（失败，回到可再点）为止。
- 这条不只是好看：`createPerMin` 是按 IP 的每分钟建房配额（默认 15），
  连点会把配额烧掉，然后收到一条与「房间满了」无关的 `建房太频繁，稍后再试`，把人带偏。
- 断线时的兜底：提交中若 socket 断开，要能回到可再点的状态，不能永久卡住。

### R3 · 弹窗在提交**之前**就把占用说清楚（推荐，同一处改动内完成）

- 大厅已经拿到了 `limits` 与公开房占用数（`Lobby.tsx:146-152`：`waitingTotal + busyTotal` / `limits.publicMax`）。
  弹窗里应当**在提交前**就显示这个占用，公开房已满时给出提示——与 `VisibilityChoice`
  今天对私人房关闭的处理（置灰 + 改写 hint 文案）是同一套语汇。
- **只提示，不禁用「创建」按钮**：客户端的计数最长滞后一个 `LIST_FLUSH_MS`（250ms）加一次广播，
  用一个可能过期的数去挡住一次**本来会成功**的建房是更坏的失败方向。准入判断永远在服务端。

### R4 · 不动的东西

- 不改协议、不改 `hub.ts` 的判断顺序与文案。服务端说的话已经是对的，问题只在它被显示在哪。
- 不改 `net/ws.ts`（禁区）。
- 不自动替玩家把可见性切到私人——那是玩家的决定，弹窗只负责把建议放在他手边。

## Acceptance Criteria

复现前置：把公开房上限调到 1 再起服务端（`MAX_PUBLIC_ROOMS=1`，见 `.env.example`）。

- [ ] **AC1**：A 浏览器建一间公开房占满 → B 浏览器打开建房弹窗、点「创建」→
      **弹窗内**出现「公开房间已满，可以创建私人房间」，弹窗仍开着。
- [ ] **AC2**：接着在同一个弹窗里把可见性改成「私人」→ 点「创建」→ 建房成功、进入房间屏；
      刚才那条错误没有残留在任何地方。
- [ ] **AC3**：`ALLOW_PRIVATE_ROOMS=0` + `MAX_PUBLIC_ROOMS=1` 时，同样的操作
      弹窗内显示「公开房间已满，稍后再试」，私人选项照旧置灰。
- [ ] **AC4**：点「创建」到收到回复之间，「创建」按钮不可再点；收到 `error` 后恢复可点。
- [ ] **AC5**：房间码加入失败（随便输一个不存在的 6 位码）→ 提示仍出现在大厅页原处，行为未变。
- [ ] **AC6**：弹窗关掉再打开 → 里面没有上一次的错误。
- [ ] **AC7**：读屏可达——弹窗内的错误带 `role="alert"`，与大厅页那条同款；
      按钮禁用态不靠颜色单独表达（见 `.trellis/spec/web/frontend/component-guidelines.md`）。
- [ ] **AC8**：`pnpm --filter @scg/web typecheck && lint && test` 全绿。

## Non-Goals

- 不做「等一个位置空出来自动重试」之类的排队。
- 不在大厅列表里预告「马上就满了」。
- 不改服务端的任何配额语义或错误码（复用既有 `server_busy`）。
