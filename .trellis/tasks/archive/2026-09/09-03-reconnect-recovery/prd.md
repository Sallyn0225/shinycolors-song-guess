# 断线重连找回与放弃重连

## Goal

掉线的玩家重新打开链接时，只要座位还在宽限期内，就能看到一个明确的
「找回对局 / 放弃重连」二选一，而不是像现在这样**连尝试都不会尝试**、
启动路径与首次访问完全一致。选择「放弃」时，留守方立刻看到「已退出房间」，
房间回到等待态可以复用。

## Background

用户 2026-09-03 在 `09-03-pvp-exit-flow` 的手动走查中发现：A 关掉标签页掉线后，
B 侧的红色「掉线了，等待重连」横幅正常显示，但 A 重新输入链接后没有任何重连入口。

根因不在服务端。服务端侧一切正常：`detach()` 保留座位、`bySeatToken` 条目仍在、
宽限期内 `reattach()` 随时可以接回。**丢的是客户端那份"证明我是谁"的凭证。**

### 确认的事实（均已核对代码）

| # | 事实 | 位置 |
|---|---|---|
| F1 | 座位凭证存 `sessionStorage`，浏览器在标签页关闭时清空；刷新（F5）能留住，关掉重开留不住 | `apps/web/src/net/ws.ts:11-37` |
| F2 | 整个重连尝试被 `socket.hasResumeToken` 一票否决：没凭证就 `return`，`hello` 里连 `resumeToken` 都不带 | `apps/web/src/App.tsx:36,58` |

| F4 | **`reattach()` 没有任何在线守卫** —— 只要 token 对得上就直接 `seat.conn = conn` 换人 | `apps/server/src/ws/room.ts:218-230` |
| F5 | 宽限 60s；WS 心跳 25s（半开连接最长 25s 后才被判定掉线） | `packages/shared/src/difficulty.ts:121`、`apps/server/src/config.ts:96` |
| F6 | `Splash` 已经接 `resume` prop，并且已经会把提示语换成「点击继续对局」——UI 挂载点现成 | `apps/web/src/screens/Splash.tsx:45,213` |
| F7 | `leaveRoom` 要求会话已入座（否则回 `not_in_room`），所以「放弃」= 先 reattach 再发 `leaveRoom`，可直接复用刚做好的 `peerLeft` 横幅，无需新增客户端消息 | `apps/server/src/ws/hub.ts:518,526-535` |
| F8 | `ws.ts` 里 `close()` 是**唯一**清凭证的地方，而 `pvp-exit-flow` 之后主动退出已不再调用它 —— 凭证一旦搬到 localStorage，退出后会留下一份指向已消失座位的残留 | `apps/web/src/net/ws.ts:193-201` |
| F9 | `ws.ts:8` 的注释「刷新/**误关标签页**能找回座位」后半句是错的，这大概是缺口长期没被发现的原因 | `apps/web/src/net/ws.ts:6-10` |

### 为什么不能只把 sessionStorage 换成 localStorage

F1 那段注释给了真实理由：同机开两个窗口会互相抢座位。而 F4 说明 `reattach()`
毫无防护。单纯换存储会让两个标签页互相把对方踢下线 —— 这正是 sessionStorage
当初被选中要解决的问题。

因此存储与守卫必须**成对**改：把"同机不抢座位"这个职责从浏览器存储隔离
搬到服务端的显式守卫上。这是本任务的核心技术决策（用户 2026-09-03 已拍板）。

## Requirements

### R1 凭证存活于标签页之外

- 座位凭证改存 `localStorage`，使新开的标签页也能读到。
- 凭证必须带过期戳，过期即视为无凭证：宽限只有 60s，一份几天前的凭证不该
  在下次打开浏览器时弹出「找回对局？」。

### R2 服务端补上在线守卫

- `reattach()` 在**座位仍持有活连接**时必须拒绝，返回 `null`。
- 这条守卫顶替 sessionStorage 原本承担的防抢座职责，是 R1 的前置条件，
  两者必须同批落地，不得只做其一。
- 现有的半开连接处理（`releaseSeatPointers`、迟到 close 不踢新连接）行为不得改变。

### R3 只在真的还能重连时才提示

- 提示出现的前提是服务端确认"这个座位现在可以被认领"。不得先弹窗、
  等用户点了才发现座位早没了。
- 因此启动时需要一次**探测**而非直接认领：现有 `hello` 是"带 token 即认领"，
  探测与认领需要区分开（具体形态见 `design.md`）。

### R4 两条路的体验分开

- **同标签页刷新**：维持现状，静默自动恢复，不弹任何选择。这条路今天是好的，
  不能因为新功能而变吵。
- **新标签页打开**：弹「找回对局 / 放弃重连」二选一。

### R5 放弃重连要让留守方知道

- 选「放弃」后：认领座位 → 发 `leaveRoom` → 留守方收到 `peerLeft`，
  看到「已退出房间」横幅并在 10s 后回到房间屏（`pvp-exit-flow` 已实现的路径）。
- 放弃方落到首页或大厅（落点见 `design.md`），本地凭证必须清除。

### R6 清理既有的凭证残留

- 修正 F9 那条错误注释。
- 补上主动退出时的凭证清理（F8）：`pvp-exit-flow` 之后主动退出不再调 `close()`，
  凭证搬到 localStorage 后这个残留会直接表现为"退出后新标签页被问要不要找回"。

## Acceptance Criteria

- [ ] A 在对局中关掉标签页 → 60s 内新开标签页打开链接 → 看到「找回对局 / 放弃重连」二选一。
- [ ] 选「找回对局」→ 回到牌面，牌面状态/记忆倒计时/当前回合截止与断线前一致；
      B 侧红色掉线横幅消失，`peer{online:true}` 已广播。
- [ ] 选「放弃重连」→ B 侧立刻看到「已退出房间」横幅（昵称正确）并在 10s 后落到 Room 屏；
      房间以 `waiting` 重回大厅列表；A 侧本地凭证已清除，再开标签页不再提示。
- [ ] 宽限已过（>60s）或房间已散时打开链接：**不弹任何提示**，与首次访问完全一致。
- [ ] 同标签页刷新（F5）仍然静默自动恢复，不弹选择框 —— 行为与本任务之前一致。
- [ ] 同机两个标签页不能互抢座位：B 标签页持有座位在线时，A 标签页拿同一凭证
      认领会被服务端拒绝，B 不掉线。
- [ ] 主动退出（`leaveRoom`）后凭证被清除，新标签页不会提示找回。
- [ ] 掉线宽限的既有行为无变化：留守方仍看到红色横幅与倒计时，
      宽限到期仍收到 `matchEnd(reason:'disconnect')`。
- [ ] `pnpm -r test` 与 `pnpm -r typecheck` 全绿；服务端新增覆盖
      「在线守卫拒绝抢座」「探测不产生副作用」「放弃重连触发 peerLeft」三条路径的测试。

## Out of Scope

- 不做跨设备找回（换一台机器继续对局）—— 凭证是本机的，不引入账号体系。
- 不改再战投票、送り札、判定等对局规则。
- 不做 PVP 战绩记录（`records.ts` 仍只服务单人模式）。
- 不修 `tools/ui-audit/probe.mjs`（另有线索记录在 `web/frontend/quality-guidelines.md`）。

### R7 半开连接期间的反馈

宽限保持 60s（见「关键决策」D1），而心跳最长 25s 才判定掉线（F5），
两者相除意味着**最坏情况下宽限的 40% 落在"座位在服务端看来仍然在线"的窗口里**。

- 触发条件：拔网线 / 断电 / 浏览器崩溃这类**不发 FIN** 的断开。正常关标签页会发 FIN，
  服务端立刻 `detach()`，不受此影响 —— 也就是说用户报告的原始场景不落在这个窗口里。
- 这段时间内认领会被 R2 的守卫拒绝。此时**不得静默放行**（那看起来和今天的 bug 一样），
  必须告诉用户座位仍被占用并自动重试，直到守卫放行或宽限到期。
- 若用户在这个窗口里选「放弃重连」：无法认领座位，因而发不出 `leaveRoom`。
  退化为本地放弃（清凭证、落首页），留守方直到宽限到期才收到
  `matchEnd(reason:'disconnect')`。这是可接受的退化，不额外加协议。

## 关键决策

- **D1 宽限维持 60s**（用户 2026-09-03 拍板）。不为手动找回调长：留守方对着冻结牌面
  干等的代价是即时且确定的，而宽限是 `difficulty.ts` 里的一个常量，
  真实使用后再调的成本极低。代价见 R7。
- **D2 存储与守卫成对改**：localStorage + 服务端在线守卫（用户 2026-09-03 拍板）。
  理由见「为什么不能只把 sessionStorage 换成 localStorage」。

## Risks

- **`net/ws.ts` 是 UI 工作的禁区文件**（`web/frontend/index.md:43-46`），理由是
  "它编码了本地开发永远复现不了的线上 bugfix"。本任务不是 UI 工作，改它是正当的，
  但改动必须最小、且逐条说明为什么不会碰到那些线上修复。
- **R2 的守卫是回归高危点**：它落在每一次重连的必经路径上。守卫写窄了会抢座，
  写宽了会把正常重连挡在门外 —— 后者比原 bug 更严重，因为它连同标签页刷新一起废掉。
