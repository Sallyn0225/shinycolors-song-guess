# CDN 选型研究（境内 VPS · 域名已备案）

调研日期：2026-08-31。价格与额度会变，接入前以官方购买页为准。

## 决定性发现：标准 CDN 过不了 WebSocket

这一条决定了整个接入形态，必须先于价格考虑。

| 方案 | WebSocket | 备注 |
|---|---|---|
| 腾讯云 CDN（标准静态加速） | **不支持** | 架构面向 HTTP 短连接，长连接会断 |
| 腾讯云 ECDN 全站加速 | 支持 | 可配 WebSocket 超时；比 EdgeOne 贵 |
| **腾讯云 EdgeOne** | **支持** | 控制台开关：站点加速 > 网络优化 > WebSocket；规则引擎可按域名/URL 细化 |
| 华为云 CDN | 仅"全站加速"类型支持 | 同样要选对类型 |

参考：<https://cloud.tencent.com/document/product/1552/73071>

### 为什么这条是硬门槛

`DEPLOY.md` 已经论证过：页面和 `/ws` **必须同源同端口**，否则 https 页面里
发 `ws://` 会被浏览器静默拦掉（只报语焉不详的安全错误，不报网络错误）。

于是只有两条路：

- **A. 整站挂支持 WS 的 CDN**（EdgeOne）：同源保持，无跨域问题，无需动
  `PUBLIC_ASSET_BASE`，也不用给 `sfx.ts` / greet 的 `fetch` 加 CORS。**首选**。
- **B. 主域名不挂 CDN，只把静态资源分流到 CDN 子域**：`/ws` 安全，但要处理
  跨域音频的 CORS（`sfx.ts:109` 和 `audio.ts:192` 都是 `fetch` + `decodeAudioData`，
  跨域必须有 `Access-Control-Allow-Origin`），改动面大得多。

## 关键：CDN 对本项目的实际收益比直觉小

**因为稳态流量全是 `no-store`，走不了缓存。**

| 流量类型 | 可否 CDN 缓存 | 月度占比推测 |
|---|---|---|
| 首屏 JS/CSS/mp4/sfx/greet | ✅ 可缓存 | 冷访问越多占比越高 |
| 封面 `/cover`、缩略图 `/thumb` | ✅ 可缓存（已带 `immutable` + 365d） | 中 |
| 对局切片 `/api/clip/*` | ❌ `no-store`，且**故意不能缓存**（缓存命中的时间差是弱旁路） | 高 |
| 环境 BGM `/api/ambience/clip/*` | ❌ 同上 | **最高**（10 KB/s 持续） |

结论：

1. CDN 只能卸掉**首屏 + 封面**，稳态的 BGM 与切片仍然吃满源站 5Mbps。
   所以 CDN **不能替代**首屏瘦身，两件事都要做。
2. 首屏瘦到 ~1.5MB 后，50 GB/月 ≈ 33,000 次冷访问，个人版够用。
3. 音频路径必须在 EdgeOne 规则引擎里显式配置**不缓存 + 回源**，
   并确认 CDN 不会剥掉或改写 `cache-control: no-store`。
4. 音频经 CDN 回源会多一跳延迟。这个游戏按**反应时间**判定而非到达时间
   （`DEPLOY.md` 检查清单最后一条），所以延迟不影响公平性，但影响手感。
   若实测起播明显变慢，可考虑让 `/api/clip` 与 `/api/ambience` 走**不挂 CDN 的子域**
   —— 注意这不违反同源要求，同源约束只针对页面与 `/ws`。
