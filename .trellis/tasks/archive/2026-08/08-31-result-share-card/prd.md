# 结算页导出战报图片

## Goal

单机结算页（`Result`）与联机对局结算浮层（`Karuta` 的 `stage === 'over'`）各新增一个「导出战报」入口：
用户填写自己的 ID，前端生成一张 Live 票根风格的战报图并下载。单机与联机是两套不同的信息结构，
共用同一副票根骨架。

同时引入一套**成绩段位体系**：按表现划分若干段，每段配称号、一句评价、一张表情小图。
段位先落在结算页网页上，战报图再把它印进去 —— 两处读的是同一份数据，不允许各写一套。

风格基底已选定：`research/style/style-3-ticket.png`（票根 / 双色印刷）。

## Requirements

### R1 入口

- R1.1 单机结算页底部按钮区新增「导出战报」，与「再来一局」「换个难度」并列。
- R1.2 联机结算浮层按钮区新增「导出战报」，不打断既有的再战投票流程（点开导出不取消已投的票）。
- R1.3 两处入口都打开同一个导出对话框组件，只是喂进去的数据不同。

### R2 ID 输入

- R2.1 对话框内有一个 ID 输入框，最长 16 字符（与联机 nickname 上限一致），前后空白裁掉。
- R2.2 填过一次后写入 `localStorage`，下次打开自动预填，可改。
- R2.3 联机场景下若 `localStorage` 无值，用本局房间里的昵称兜底预填。
- R2.4 ID 留空也能导出，图上该位置显示占位文案而不是空白或 `@`。

### R3 单机战报内容

- R3.1 得分 / 满分、难度名。
- R3.2 答对数 / 总题数、正确率、平均用时、片段长度。
- R3.3 逐题结果条：答对 / 答错 / 未作答三态可区分。
- R3.4 曲目清单：封面缩略图、曲名、答对与否、单题用时；答错时显示玩家选了什么。
      题目多时截断并注明剩余数量。
- R3.5 一个按正确率变化的判定印章。

### R4 联机战报内容

- R4.1 胜 / 负 / 平，以及胜负原因（先清空自陣 / 对手断线判负 等）。
- R4.2 双方 ID 对阵展示（你的 ID vs 对手昵称）。
- R4.3 回合数。
- R4.4 「你 / 对手」两列对比：剩余自陣、取牌、お手つき、平均反应。
- R4.5 若发生过服务端反应时间校正，图上也要标出（与页面上的公示口径一致，不能只在网页说）。
- R4.6 一个按胜负变化的判定印章。
- R4.7 联机战报**不含**曲目清单与逐题条（这两项联机端根本没有数据）。

### R5 图片产出

- R5.1 导出 PNG，竖版 2:3，2 倍像素密度。
- R5.2 对话框内展示等比缩放的预览，用户能在下载前看到成品。
- R5.3 提供下载；文件名带上 ID 与日期，便于区分多张。
- R5.4 移动端在 `navigator.share` 可用时优先走系统分享，否则退回下载。
- R5.5 下载失败或浏览器拦截时给出可见提示，并保留预览图供长按保存。

### R7 成绩段位（称号 / 评价 / 表情）

- R7.1 定义一套段位表，每段包含：段位 id、称号、一句评价描述、表情图资源、配色。
- R7.2 单机按**得分率**（`score / maxScore`）分段——它同时反映了答对、速度奖励与重听扣分，
      比单看正确率更能代表这一局。分段边界与段数见 `design.md`。
- R7.3 联机按**胜负**分段，并用本局表现（お手つき、取牌差）做细分，使同为「胜」也能区分出打法。
- R7.4 段位表是单一数据源：结算页网页与战报图从同一处读取，禁止两边各写一份文案。
- R7.5 结算页网页展示段位：单机替换现有的 `verdictLine` 一行文案，联机加在胜负字样附近。
- R7.6 战报图上，称号、评价、表情图三者都要出现。
- R7.7 表情图暂用占位素材，路径与命名按正式资源约定好，将来替换文件即可、不动代码。
- R7.8 表情图加载失败或尚未就绪时，网页与战报都要能正常显示（降级为不画图，不留破图、不塌布局）。

### R6 约束

- R6.1 不引入新的运行时依赖，用原生 Canvas 2D 绘制。
- R6.2 不修改 `src/audio.ts`、`src/net/ws.ts`、`src/api.ts` 与 `src/features/` 下的既有文件。
- R6.3 不新增后端接口，战报所需数据全部来自结算页已有的数据。
- R6.4 玩家 ID 只留在本地，不上报服务端。
- R6.5 生成图里不出现 `THE IDOLM@STER` / `283 PRODUCTION` 之类的版权字样（风格稿里模型自己加的，要去掉）。
