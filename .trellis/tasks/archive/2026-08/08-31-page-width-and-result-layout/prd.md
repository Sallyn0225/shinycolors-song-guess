# 收窄页面主列宽并重构结算页布局

## 背景

用户在实际使用中提出三条前端观感问题。经 Playwright 实测(dev server, 1366×678 与 1920×990)全部复现。

参照系是用户自己给的:**1v1 房间页(`--page-narrow: 760u`)的宽度是舒服的**,而首页 / 单人猜歌 / 结算三页用 `--page-main: 1120u`,宽了 47%。

## 问题与实测证据

### P1 三页主列过宽

`apps/web/src/index.css:176` 的 `--page-main: calc(1120 * var(--u))` 被 `Start.tsx:117`、
`Play.tsx:219`、`Result.tsx:63` 三处引用。

实测 1366×678(`--u` 触底 0.78):

| 页面 | 主列宽 | 症状 |
|---|---|---|
| Start | 874px | EntryBar 里「简单」在最左、「题数/片段/限时/重听」四项在最右,视线要横扫约 600px 才能把难度名和它的参数连起来 |
| Play | 874px(选项条 796px) | 曲名靠左,右侧留出约 400px 空白 |
| Result | 874px | 曲目行的曲名与用时之间空出约 600px |

### P2 结算页列表把页面拉长,按钮被推出视野

`Result.tsx:138` 的 `<ol>` 直接铺在页面流里,高度随题数线性增长。

实测 1366×678,**简单难度 10 题**:`docH 1142` / `vpH 678` —— 页面是视口的 1.68 倍,
底部三个按钮(再来一局 / 换个难度 / 导出战报)完全在折线之下。困难难度 20 题会再翻近一倍。

### P3 「换个难度」文案与行为不符

`Result.tsx:234` 的按钮标签是「换个难度」,但 `onClick` 是 `onHome`,行为是返回首页。
首页确实**可以**换难度,但那是返回首页之后的事,不是这个按钮做的事。

## 与既有设计约束的冲突(已实测排除)

`DESIGN.md` 的 Layout 一节明确写着:

> `--page-main` 原来是 `1300u`…收到 `1120u` 后两侧留白 15%(1440)到 20.8%(1920)。
> **再窄就不行——选项条是「整宽横条」的形状语汇,1366 档再收会短到失去这个语义。**

这条记录否定的正是本任务要做的事,因此**先实测再决定**,结论是这条顾虑不成立:

- 900u @ 1366 档,Play 的选项条实测 **624 × 75px = 8.3 : 1**,依然是无可争议的横条
  (1120u 时是 796 × 75 = 10.6 : 1)。横条语义在这个比例上没有任何损失。
- 收窄**不增加**任何一页的高度。Start 页 `docH` 在 1120u 与 900u 下同为 **694**(1366 档)、
  同为 **990**(1920 档);Play 页两档都是 `docH 678 == vpH 678`,一屏装下。
  原因是 `.sc-bar` 与 `.sc-revealslot` 是**定高**(The Constant-Height Rule),
  而 EntryBar 的说明文字在 900u 下仍是单行。
- 因此 `Start.tsx:100-114` 记录的「1366×678 只剩 3.4px 余量」这条纵向预算不受影响。

**本任务需要同步修订 DESIGN.md 的这段结论**,把「1120u 是下限」改成实测后的新事实,
否则下一次有人读 DESIGN.md 会把这次改动当成违规。

## 需求

### R1 三页主列收窄到 900u

- `--page-main` 从 `1120u` 改为 `900u`,Start / Play / Result 三页同时受益。
- 不改 `--page-board`(牌场 1000u)、`--page-narrow`(大厅/房间 760u)、`--page-card`(结算卡 520u)。
- 保持 `mx-auto` 居中与现有 `px-*` 内边距不变。

### R2 结算页曲目列表改为页内定高滚动区

- 列表装进一个高度受限的容器,容器内纵向滚动,容器外的页面不再随题数增长。
- **验收基准:简单(10 题)与困难(20 题)两种难度下,结算页的 `docH` 必须相等** ——
  这是「页面不再被列表拉长」的可测量定义。
- 底部按钮行在 1366×678 档必须落在首屏可达范围内(允许极小幅滚动,不允许像现在这样差 460px)。
- 滚动区必须有**可见的边界感**,让用户看得出「这里面还能滚」,不能是一个无提示的截断。
- 键盘可达:滚动容器要能被 Tab 聚焦并用方向键滚动(否则纯键盘用户拿不到列表下半部分)。

### R3 按钮文案改为「返回首页」

- `Result.tsx:234` 的「换个难度」改为「返回首页」。`onHome` 回调与 `variant="ghost"` 不变。

## 非目标

- 不动 `Lobby` / `Room` / `Karuta` / `Splash` 四屏的宽度。
- 不动 `audio.ts` / `net/ws.ts` / `api.ts` / `features/*`(spec 明令的禁区)。
- 不改结算页的信息构成(分数、段位、四项统计、逐题字段都保留)。
- 不改「再来一局」「导出战报」的文案与行为。
