## 需求

### R1 — 授权声明必须区分代码与素材

这是本任务的核心难点，不是走流程。

仓库里两类内容的权属完全不同：

| 内容 | 权属 |
|---|---|
| `apps/` `packages/` `tools/` 全部代码 | 作者本人，可自由授权 |
| `apps/web/public/` 下 94 个素材（greet / idol / emote / bg / brand / mark） | **万代南梦宫**，作者无权转授 |
| `apps/web/public/sfx/` 6 个音效 | CC0，已有 `CREDITS.md` |
| `design-extract-output/SHINYCOLORS-DESIGN-LANGUAGE.md` | 源自官网，第三方 |

**一个统一的 LICENSE 文件会做出错误的法律陈述** —— 用 MIT 覆盖整个仓库，
等于声称有权把万代的素材按 MIT 转授给任何人。必须拆开：LICENSE 只管代码，
另有一份 NOTICE 说明素材的实际归属与非官方性质。

### R2 — README 要回答「为什么我 clone 下来跑不起来」

`songs/`（1.8GB 源音源）与 `assets/`（228MB 构建产物）都不入库。
克隆者拿到的是一个**没有曲库的空壳**：`Catalog.load()` 会直接抛
「曲库为空——请先跑 pnpm assets all」。

不在 README 里显著说明，必然收到重复 issue。而且这件事**不能靠提供下载解决**
（那就是分发音源），只能说明「需自备音源」。

### R3 — 复核既有文档

`DEPLOY.md:3` 现在写着「仓库保持私有，不要公开部署到不受控的公网」。
公开之后这句话与事实矛盾。需要改成反映实际选择的表述，而不是删掉——
那条警告的技术内容（切片是派生物、开放房间列表的暴露面）依然成立。

### R4 — 公开会暴露提交邮箱

76 个提交都带 `z1921531571@outlook.com`。这是 git 的正常行为，不是泄漏，
但公开前应当是一个**知情确认**而非事后发现。若不希望暴露，
GitHub 提供 noreply 邮箱，但改历史邮箱需要 rewrite——**在公开前做代价为零，公开后代价极高**。

## 验收标准

- [ ] `LICENSE` 存在，且其适用范围在文件内明确限定为代码
- [ ] `NOTICE`（或 README 中的等效章节）声明第三方素材归属与非官方性质
- [ ] `README.md` 含：项目简介、非官方声明、**自备音源说明**、快速开始、文档索引
- [ ] `DEPLOY.md` 开头的私有性警告已按实际选择改写，技术内容保留
- [ ] R4 的邮箱问题已向用户确认（保留现状 / 或在公开前 rewrite）
- [ ] `git status` 干净，`.gitignore` 覆盖全部不入库目录（复核而非重写）
- [ ] 公开动作本身由用户执行或明确授权后执行
