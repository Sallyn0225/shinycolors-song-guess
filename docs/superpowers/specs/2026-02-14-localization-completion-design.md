# 本地化补全设计

## 目标

以提交 `33a0967dd6876e247331ac838628c5e05f4d88e0` 引入的 i18next 结构为基础，补全 `apps/web/src` 中所有面向用户的硬编码文本，使中文、日文、英文三种语言在运行时都能获得对应文案；中文沿用网页模板现有中文，不重新翻译。

## 范围

- 审计所有 `.tsx` 用户界面文件，覆盖正文、按钮、占位符、状态提示、弹窗、`aria-*`、`sr-only` 文本。
- 不迁移开发注释、测试描述、歌曲/角色/组合等业务数据中的固有名称。
- 保持当前工作区对 `apps/web/vite.config.ts` 的未提交修改不变。

## 实施方式

1. 主会话建立统一的翻译 key 结构，并将组件中的硬编码改为 `useTranslation()` / `t()` 调用；需要富文本或日文标记时使用现有 React 结构或 `Trans`，不把 HTML 标记塞入普通翻译字符串。
2. 并行分派两个翻译 subagent：每个 agent 只编辑一个资源文件，分别负责 `locales/ja.json`、`locales/en.json`，根据统一 key 翻译自然、完整且语义一致的文案；`locales/zh.json` 由主会话直接搬运模板中的现有中文。
3. 主会话检查三份 JSON 的 key 集合、变量占位符集合和组件引用一致性，解决冲突并完成集成。

## 验证

- 三份 locale JSON 均可解析，key 集合完全一致。
- 代码搜索不再发现用户可见的目标硬编码文本。
- TypeScript 构建/测试通过；至少运行项目现有的 lint/typecheck/test 命令。
- 工作区 diff 只包含本任务改动及原有 `vite.config.ts` 用户修改。
